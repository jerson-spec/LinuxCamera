## 2. 当前已知事实

- 摄像头请求 1024×600，实际返回 **800×600 YUYV**；
- `bytesperline = 1600 = 800 × 2`；
- LCD 为 **1024×600**；
- 画面显示在左上角 800×600，右侧 224 像素黑色；
- 黑边是分辨率/宽高比不匹配，不是 bug；
- 单帧预览由 `lcd.ini` 的 `display_time` 决定保持时间；
- 当前没有连续循环。

## 5. 下一步：v0.5 连续预览

### 第 1 步：单缓冲连续循环

在 `test_camera_preview.c` 基础上：

```text
while (running) {
    poll(timeout);
    DQBUF;
    yuyv_to_rgb;
    QBUF;
    display;
    fps;
}
```

要求：

- `QBUF` 尽早；
- `poll` 超时；
- Ctrl-C 退出；
- 每秒打印 FPS/耗时；
- 先接受撕裂。

### 第 2 步：测性能

记录：

```text
fps
capture_ms
convert_ms
display_ms
```

如果 FPS 低：

- 把浮点 YUV 转整数/查表；
- 不再逐像素 `lcd_put_pixel()`；
- 直接写 RGB565，按行处理；
- 减少一次 memcpy。

### 第 3 步：双缓冲

- `yres_virtual = 2 * yres`；
- 两个显示 buffer；
- `FBIOPAN_DISPLAY`；
- 写后台 buffer，显示前台；
- 观察撕裂是否消失。

### 第 4 步：10 分钟稳定性

- 连续运行 10 分钟；
- 记录 FPS 波动；
- 检查 `/proc/<pid>/status` 的 VmRSS；
- Ctrl-C 清理。

### v0.5 验收

- [ ] 10 分钟不崩；
- [ ] FPS 可打印；
- [ ] 无内存增长；
- [ ] Ctrl-C 干净退出；
- [ ] 双缓冲可用。

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 逐像素显示太慢 | FPS 低 | 直接写 RGB565，按行处理 |
| 单缓冲撕裂 | 观感差 | 双缓冲 + FBIOPAN_DISPLAY |
| `bytesperline` 不匹配 | 画面斜 | 加 stride 参数 |
| 摄像头分辨率 < LCD | 黑边 | 1:1 接受，v1.0 做 letterbox |
| 配置结构膨胀 | 维护困难 | v0.5 后再拆 |
| 继续加测试程序 | 目录失控 | 先 v0.5，再抽 camera/display 模块 |
| 提前做触摸/OSD/网络 | 主线延迟 | 先连续预览 |
