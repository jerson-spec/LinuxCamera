## 2. 当前已知事实

- 摄像头请求 1024×600，实际返回 **800×600 YUYV**；
- `bytesperline = 1600 = 800 × 2`；
- LCD 为 **1024×600，32bpp**；
- 画面显示在左上角 800×600，右侧 224 像素黑色；
- 黑边是分辨率/宽高比不匹配，不是 bug；
- 摄像头在 800×600 YUYV 下只有 15/10/5 fps 三档，实测 15.0 fps；
- 连续预览用 4 buffer + `poll` 超时 + Ctrl-C 退出，双缓冲走 `FBIOPAN_DISPLAY`。

## 5. v0.5 实施记录（已完成）

### 第 1 步：单缓冲连续循环

在 `test_camera_preview.c` 基础上：

```text
while (running) {
    poll(timeout);
    DQBUF;
    yuyv_to_rgb;
    QBUF;
    display;
    fps;
}
```

要求：

- `QBUF` 尽早；
- `poll` 超时；
- Ctrl-C 退出；
- 每秒打印 FPS/耗时；
- 先接受撕裂。

### 第 2 步：测性能

记录：

```text
fps
capture_ms
convert_ms
display_ms
```

如果 FPS 低：

- 把浮点 YUV 转整数/查表；
- 不再逐像素 `lcd_put_pixel()`；
- 直接写 RGB565，按行处理；
- 减少一次 memcpy。

### 第 3 步：双缓冲

- `yres_virtual = 2 * yres`；
- 两个显示 buffer；
- `FBIOPAN_DISPLAY`；
- 写后台 buffer，显示前台；
- 观察撕裂是否消失。

### 第 4 步：10 分钟稳定性

- 连续运行 10 分钟；
- 记录 FPS 波动；
- 检查 `/proc/<pid>/status` 的 VmRSS；
- Ctrl-C 清理。

### v0.5 验收（全部通过，2026-11-08）

- [x] 10 分钟不崩；
- [x] FPS 可打印（15.0）；
- [x] 无内存增长（6324 kB 恒定）；
- [x] Ctrl-C 干净退出；
- [x] 双缓冲可用（`FBIOPAN_DISPLAY` 全程无错误）。

### 下一步：W3 性能与适配

目标不是提高 800×600 的 fps（摄像头锁死 15），而是：

1. 定点化 YUYV→RGB：`conv` 35.1 ms → 目标 <15 ms；
2. 融合转换与上屏、按行写：`draw` 30.6 ms → 目标 <8 ms；
3. 单帧 <25 ms，为 OSD/JPEG/640×480@30 留出余量。

验收：

- [ ] 800×600 仍 15fps，CPU 忙占比从 98% 降到 40% 以下；
- [ ] 640×480 能跑满 30fps；
- [ ] 画面与优化前一致（逐像素对比或肉眼色条）。

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 逐像素显示占 30 ms | CPU 余量只剩约 2%，加功能就掉帧 | W3：按行写 + 定点 |
| 双缓冲 pan 不被驱动支持 | 退回单缓冲 | 已实现自动降级 |
| `bytesperline` 不匹配 | 画面斜 | W3 加 stride 参数 |
| 摄像头 800×600 只能 15fps | 帧率上不去 | 接受；要 30fps 走 640×480 |
| 首帧延迟 1–1.6 s | 影响"开机 3 秒出图" | v1.0 处理 |
| 配置结构膨胀 | 维护困难 | v1.0 前再拆 |
| 提前做触摸/OSD/网络 | 主线延迟 | 先 W3 再 v1.0 |
